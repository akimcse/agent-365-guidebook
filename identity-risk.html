SECTION 03

권한 — 부여 vs 실사용Entra ＋ Graph

Microsoft는 “에이전트가 실제 사용 중인 상속 범위·역할을 감사하고 사용하지 않는 권한을 제거할 것”을 공식 권고합니다. 이를 수행하려면 부여와 실사용을 각각 다른 경로에서 확인해 대조해야 합니다.

A부여된 권한 (정적 구성)

에이전트에 무엇을 허용했는지를 확인합니다. 두 곳에서 볼 수 있으며 목적이 각각 다릅니다.

① 에이전트별 권한·로그인
Entra 관리센터 ▸ Entra ID ▸ Agents ▸ Agent identities
에이전트 선택 → 이름·상태·소유자·스폰서·부여된 권한·sign-in 로그 ② 응용/위임 권한 구분
M365 관리센터 ▸ 에이전트 상세 ▸ Permissions 탭

B실제 사용된 권한 (런타임)

Microsoft Graph 활동 로그가 토큰 클레임의 실제 범위·역할과 실제 API 요청을 기록합니다. 과다 권한을 식별할 수 있는 유일한 근거입니다.

주요 필드 — Scopes(위임 범위) · Roles(앱 역할) · ServicePrincipalId · RequestUri · ResponseStatusCode · SignInActivityId 전제조건 — Entra ID P1/P2 + Azure Monitor 진단 설정 + Azure 구독. 기본 활성이 아닙니다. 조회 위치 — Entra 관리센터에서는 조회 불가. Azure Portal ▸ Log Analytics ▸ 로그에서 MicrosoftGraphActivityLogs KQL 조회 (또는 Sentinel · Storage · Event Hubs) 유의 — 진단 설정 구성 이전 요청은 소급 조회가 불가하므로 도입 초기 활성화가 필요합니다.

!OBO 흐름에서는 대상이 바뀝니다

에이전트가 자기 신원으로 접근할 때만 에이전트 대상 정책이 적용됩니다. 사용자를 대신하는(OBO) 흐름에서는 사용자가 주체이므로 정책을 사용자·그룹에 걸어야 하며, 위험도 사용자에게 귀속됩니다.

모든 사용자 대상 정책은 에이전트 사용자 계정을 포함하지 않습니다.

!차단이 적용되지 않는 구간

조건부 액세스는 블루프린트가 에이전트 신원·사용자 계정을 생성하려고 Graph 토큰을 받는 시점과 중간 토큰 교환 구간에는 적용되지 않습니다.

Power Platform 방화벽이 활성 집행 모드이면 관리센터에서 시작한 조치가 실패하며 적용되지 않습니다.
