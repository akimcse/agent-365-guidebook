Purview · 데이터 보안 · 감사

에이전트가 다루는 데이터를 Microsoft Purview로 어떻게 분류·보호·감사하는지 정리합니다. 실제 분류·탐지 엔진(SIT·Trainable Classifier·EDM)과 이를 소비하는 정책(DLP·Communication Compliance·IRM), 이를 집계해 보여주는 DSPM을 계층으로 구분하고, 어디까지가 Purview 고유 기능이고 어디서부터 Agent 365가 필요한지를 명확히 합니다.

라이선스 표기제품 기본 해당 제품 라이선스만으로 사용Agent 365 Microsoft Agent 365 필요시행 예정 문서상 Agent 365 요구이나 아직 미시행추가 별도 구매·종량제(PAYG) 필요

SECTION 04

프롬프트·응답 본문 위치Purview E5AI 관측성 = Agent 365＋PAYG

“감사 로그에 본문이 없다”는 설명과 “Purview에서 프롬프트·응답을 볼 수 있다”는 설명이 상충하는 것처럼 보이지만, 실제로는 두 저장소가 분리되어 있습니다.

감사 레코드 — 메타데이터만

감사 솔루션의 로그에는 사용자와 에이전트 간 상호작용의 전체 텍스트나 대화 기록이 포함되지 않으며, 대화 스레드 ID만 기록됩니다.

호출 사실, 접근 리소스 참조, 민감도 레이블, 정책 적용 여부 등 메타데이터 확인용

DSPM — 본문(트랜스크립트)

대화 텍스트는 감사 이벤트와 별도로 저장되며, DSPM에서 해당 이벤트로부터 트랜스크립트에 직접 접근할 수 있습니다.

수집 정책의 콘텐츠 캡처를 명시적으로 활성화해야 프롬프트·응답 전체가 저장됩니다. 켜지 않으면 민감정보 탐지 결과로만 제한됩니다. 단, 생성형 AI와 공유된 첨부 파일의 본문은 캡처 대상에서 제외됩니다.
